# Public site and repository audit — September 23, 2026

[← Back to Chordleaf](../README.md) · [Deployment](deployment.md) · [Security policy](../SECURITY.md)

## Executive summary

Chordleaf's source and production site are public. The preferred address is `https://chordleaf.com/`; `https://www.chordleaf.com/` returns a permanent redirect to it. Vercel requires authentication for preview deployments. The repository has an MIT license, contribution and security policies, an active protected `main` branch, and automated checks. No exposed secret or known dependency advisory was found in the scans described below. That result is limited to the patterns, commit refs and advisory data available at the time of the audit.

The largest remaining operational work is to watch public web-import usage and provider availability, confirm actual Google indexing, and perform human accessibility checks on real devices. There is no evidence here of a launch-blocking defect, but automated checks cannot guarantee security or accessibility.

## Scope and evidence

Reviewed the deployed HTTP responses, built HTML, Vercel and GitHub settings, source and publicly reachable Git history, dependencies, documentation, four published images, automated browser checks and a mobile Lighthouse run. The Git review included `main`, release tags and pull-request refs; it did not rely only on the latest tree. This is a targeted application and release audit, not a penetration test, formal legal review or accessibility certification.

## Performance and accessibility

A Lighthouse 13.5.0 mobile run against the public production homepage before this audit's SEO/accessibility fixes scored **99 performance, 92 accessibility, 100 best practices and 92 SEO**. It reported FCP and LCP of **1.5 s**, total blocking time **0 ms**, CLS **0**, and Speed Index **2.5 s**. These are one synthetic run, not field Core Web Vitals or a guarantee for slower devices. Export libraries are lazy-loaded, and fonts are self-hosted.

That run found a root canonical pointing to `/en/`, an unnamed export button at the mobile breakpoint, a language control whose accessible name omitted its visible `EN`/`ES` label, and no main landmark when the workspace was empty. This update gives the root page a self canonical and sitemap entry, labels Export, includes the language code in its accessible name, and exposes the empty state as a main landmark. On the rebuilt local server, Lighthouse scored **93 performance, 100 accessibility, 100 best practices and 100 SEO**, with LCP **2.6 s**, TBT **0 ms** and CLS **0.002**. The difference in performance from the production run is an environment difference, not evidence of a regression. Re-run Lighthouse after deployment to verify the live outcome. The app's static fallback still provides a main landmark before JavaScript starts.

## Verification limits

Gitleaks detects configured secret patterns, not arbitrary private prose or rights issues. `pnpm audit`, Dependabot and CodeQL depend on their current advisory databases and rules. A clean scan does not prove that software is vulnerability-free. Lighthouse measures a specific device simulation and run; it does not measure every user's experience. Search Console submission can take time to produce crawl or indexing reports.

Use invented song excerpts and synthetic files in issues, pull requests and screenshots. Report suspected vulnerabilities through [GitHub's private vulnerability reporting](https://github.com/antoniomml/chordleaf/security/advisories/new), following [SECURITY.md](../SECURITY.md).
